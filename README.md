# Rank

Open, deterministic college football rankings for **every FBS and FCS team**. Live at **https://rank.sam-bennett.dev**.

**One spring graph.** Every game is a spring that wants its winner 7 × (1 + 1/2 + … + 1/margin) points above its loser, so the first point is worth 7, the second 3.5, the third 2.33, and each extra point counts less. Each spring is as strong as the result was surprising: an upset or a win over a good team pulls hard, a good team beating a bad one barely pulls, so cupcake blowouts don't drag anyone down. Solving the whole graph (repeated until the spring strengths settle) gives every team a strength, and from it a **quality**: 100 × its chance of beating an average team, from 0 to 100. Quality is the ranking.

Two more boards come from quality:

- **Résumé:** points per game. A win earns the beaten team's quality; a loss costs 100 minus the winner's quality.
- **Schedule:** the average quality of the opponents played.

No home field or head-to-head rules.

- **Every team starts at zero.** No preseason, polls, recruiting or conference bonus. FBS and FCS share one graph, and results against lower-division teams count.
- **Explainable game by game.** The team page shows every game's résumé points and the team's quality, résumé and schedule ranks.
- **Measured.** On 2014–2019, where the settings were chosen, the weekly rankings pick 70.4% of next week's winners and the final ranking has the winner above the loser in 83.1% of games (69.2% and 82.7% on 2021–2026). `research/springs.py` reproduces both.
- **Reproduce every number.** The Node scripts and the browser share one engine; Recompute on the method page rebuilds every published file byte for byte.

Matchup odds come from a separate calibrated margin model and never change the ranking. See [methodology](docs/METHODOLOGY.md).

## Run

Requires Node 22+.

```sh
npm ci
npm run dev
npm run typecheck
npm test
npm run compute
npm run verify
npm run build
npm run backtest -- --history 2021-2025   # matchup odds, walk-forward
python3 research/springs.py 2014-2019      # ranking accuracy (needs numpy)
```

## Data and audit

```text
data/seasons/<year>/teams.csv         configured teams
data/seasons/<year>/games.csv         scores, sites, kickoffs and schedule
data/seasons/<year>/plays.csv         condensed public play-by-play
data/seasons/<year>/config.json       algorithm version, spring and matchup settings
data/rankings/<year>/<snapshot>.json  quality, résumé, schedule, every game's springs, and game odds
data/index.json                       available seasons and snapshots
```

Each ranking file lists ranked FBS/FCS teams in `teams` with their `height` (quality, 0–100: the ranking), `strength` (points better than average), `resume` and `resumeRank`, `schedule` and `scheduleRank`, and each board's weekly movement (`change`, `resumeChange`, `scheduleChange`), and every counted game in `springs` with its `margin`, `spring` (spring strength), `win` (résumé points the winner earned) and `loss` (résumé points the loser lost). Lower-division opponents are on the graph too and appear, unranked, in `opponents`. `config.classifications` selects the ranked field; `opponentClassifications` can keep additional divisions as inputs. All snapshots use calendar cutoffs.

## Update results

Get a free key at <https://collegefootballdata.com/key>, then:

```sh
CFBD_API_KEY=... npm run fetch -- 2026
npm run fetch-plays -- 2026
npm run compute
npm run verify
```

Commit the changed data. GitHub’s **Update data** workflow uses the `CFBD_API_KEY` repository secret to refresh and publish automatically.

## Deploy

GitHub Settings → Pages → Source: **GitHub Actions**, with custom domain `rank.sam-bennett.dev`. The DNS CNAME for `rank` points to `sambennettdev.github.io`. Add the API secret and run **Update data** once.

## Layout

```text
src/engine/  spring graph, résumé and schedule, matchup model, chronology and pipeline
scripts/     fetching, computation, verification and backtesting
web/         static TypeScript site, sharing the same engine
tests/       spring math, matchup model, chronology and determinism
research/    reproduces the ranking's accuracy on past seasons
docs/        full methodology
```

`tests/fixtures/demo` is fictional, generated by `npm run demo`. Logos load from ESPN’s CDN by team ID.
